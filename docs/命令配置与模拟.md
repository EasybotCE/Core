# 文本命令配置与模拟解析

本批完成版本 1 文本命令配置校验、单条命令匹配、假设身份授权和预期回复生成。**没有接入真实消息触发或投递**，不执行 Minecraft 命令、PAPI、脚本或主机 shell。Minecraft 桥接继续暂缓，JS 独立进程运行时仍待实现。

## 配置

命令继续使用 `kind: "commands"` 的 Record；`detail` 是以下 JSON 的字符串。创建、更新和 `POST /api/commands/validate` 使用同一校验逻辑。预检接收 `detail` 字符串，返回 `valid:true`、`persisted:false`、`runtimeAvailable:false`，不写入配置。

```json
{
  "schemaVersion": 1,
  "prefix": "/",
  "match": "regex",
  "triggers": ["问候 (.+)", "hello (.+)"],
  "permission": "all",
  "identity": "",
  "action": "text",
  "reply": "{sender_name} 向 {arg1} 问好"
}
```

- `prefix` 可为空，最多 32 字节，不含空白或 NUL。消息必须从此前缀开始。
- `match` 为 `exact` 或 `regex`，大小写敏感，不自动去除消息两端空白。精确模式必须完整等于关键词，不接受额外参数。
- `triggers` 允许 1～16 条，不重复，每条最多 512 字节；精确关键词不含空白。正则使用 Go RE2 语法，对去除前缀后的整条消息匹配，最多 9 个捕获组；不支持反向引用或 lookaround。多个表达式按列表顺序取首个匹配。
- `permission` 为 `all`、`admin`、`owner`、`bound` 或 `custom`。`custom` 必须设置 1～120 字节的 `identity`，其他权限须留空。
- `action` 当前只能为 `text`；不接受未实现的执行动作。
- `reply` 为 1～4000 字节，变量只允许 `{sender_name}`、`{user_id}` 和已有捕获组 `{arg1}` 至 `{arg9}`。如果某条别名表达式捕获组较少，缺少的参数展开为空。展开仅执行一次，用户输入中的花括号或命令样式文本按原文保留。预期回复超过 16000 字节时拒绝生成。

现有旧命令在启动时保留原始 JSON、enabled 和时间，不做自动迁移。可读取或删除；更新或模拟前必须显式转为版本 1。命令不建立群组、服务器或身份记录引用，不增加数据库迁移版本；旧配置错误由单条模拟和批量诊断报告。自定义身份在本批仅作模拟标识，尚无身份成员管理服务。

## 模拟接口

`POST /api/commands/simulate` 使用现有管理会话鉴权。有两种互斥输入方式：

1. 已保存命令：提供 `id`，后端读取该命令的 detail 和 enabled；不能同时提供草稿覆盖。
2. 草稿：提供 `detail` 字符串和明确的 `enabled` 布尔值，不保存记录。

例如：

```json
{
  "id": "命令记录 ID",
  "message": "/问候 世界",
  "context": {
    "userId": "test-user",
    "senderName": "测试用户",
    "verified": false,
    "role": "member",
    "bound": false,
    "identities": []
  }
}
```

`context` 是管理员提供的**假设输入**，不代表真实角色、绑定或权限。除全员权限以外，只有 `verified:true` 且 userId 非空才进一步判定：管理权限接受 admin/owner，群主权限只接受 owner，绑定权限检查 bound，自定义权限要求 identities 中存在精确身份标识。未知角色不获得管理权限。未来真实运行时必须从可信平台和绑定服务生成上下文，不能信任消息内声明。

响应始终声明 `simulated:true`、`executed:false`、`runtimeAvailable:false`，并返回 `matched`、`allowed`、捕获参数及允许时的 `reply`。`reason` 为：

| reason | 含义 |
| --- | --- |
| `disabled` | 命令停用，不匹配或授权 |
| `not_matched` | 前缀或内容不匹配 |
| `permission_denied` | 已匹配，假设身份无权限，不返回回复 |
| `reply_too_long` | 展开超限，不返回回复 |
| `preview_ready` | 已生成预期回复，未实际发送 |

消息最多 8192 字节，userId 最多 128 字节，senderName 最多 512 字节，身份列表最多 32 项。配置/输入无效返回字段错误 400，命令不存在或 ID 类型不匹配返回 404，未登录返回 401。

模拟过程不修改配置、冷却或执行状态，不调用适配器/Bridge，不记录测试消息和预期回复正文。HTTP 访问元数据仍遵循现有日志策略。当前只评估一条命令，未检查命令之间的匹配冲突、平台/群/服务器范围、冷却或速率限制。

## 管理台和验证边界

命令编辑窗口提供前缀、匹配方式、关键词、权限和回复表单，以及草稿模拟区。旧版 JSON 保留原文，只有明确点击替换草稿才切换为版本 1 示例；取消不会写入。模拟结果在修改配置或测试身份后失效，过期请求结果不覆盖新草稿。

本地自动化测试覆盖五种权限允许/拒绝、未知或未验证角色拒绝、完整匹配、捕获与单次模板展开、超限拒绝、停用、无效动作、保存失败不改数据、旧配置重启保留、HTTP 鉴权、只读模拟与正文不进日志。浏览器人工交互、真实账号触发/收发均未验收；测试和前端构建不代表命令运行时已完成。

## 多命令冲突诊断

`POST /api/commands/diagnose` 接收 `message` 和同格式的假设 `context`，诊断所有已保存且启用的命令。单个无效或旧版配置作为该条 `error` 返回，不阻止其他命令；停用命令仅计数跳过。返回每条结果、matched/allowed/invalid/disabled 计数及 conflict。匹配超过一条即 conflict=true，包括被权限拒绝的匹配，避免以测试身份掩盖关键词重叠。排序按记录 ID 固定，不代表执行优先级；不选择赢家，不发送消息。

管理台命令页提供诊断区，修改测试消息、身份或命令列表后清除旧结果。最多诊断 500 条记录，超过时返回 400；请求取消时停止后续评估。身份标识单项最多 120 字节。单命令草稿模拟仍保留，诊断不检查尚未实现的平台范围、冷却和真实绑定。自动测试覆盖空列表、鉴权、冲突、权限、旧配置隔离、停用、输入上限及无写入；浏览器人工验收待完成。

## Draft PR 人工验收清单

用户明确允许先创建 Draft PR；以下人工操作尚未执行，不应据此合并。

1. 启动测试实例，登录后在命令页新建默认文本命令；输入 `/help`，应预览问候，未发出平台消息。
2. 新建第二条同关键词命令，在命令页批量诊断；应显示冲突。将第二条停用再诊断，应无冲突且跳过停用数增加。
3. 将权限改为管理员，未验证身份时拒绝；勾选已验证并选择管理员时允许，实际执行仍为否。
4. 正则设置 `echo (.+)`，回复 `{arg1}`，输入 `/echo {user_id}`；预期回复保留 `{user_id}` 原文。
5. 在测试数据库准备旧版命令，编辑时应保留完整原 JSON；取消不改数据，诊断应仅报告该条配置无效，其余命令照常诊断。
6. 模拟请求在进行中时更改输入，旧结果不应覆盖新输入。退出登录后再次调用接口应返回 401。
