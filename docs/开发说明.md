# EasybotCE 开发说明

仓库根目录包含 Go 管理服务和 Vue 3 管理台。默认使用 SQLite，也可通过配置接入 MySQL 或 PostgreSQL。普通用户的便携包使用方法见 [项目首页](../README.md)。

## 构建与本地运行

开发环境要求：Go 1.24+、Node.js 20.19+。在仓库根目录执行 `node build.mjs`，即可安装依赖、构建页面、编译程序并在 `release/` 中生成便携包。

手动调试时，从仓库根目录执行以下 PowerShell 命令：

```powershell
cd web
npm ci
npm run build
cd ..
$env:EASYBOT_CONFIG = Join-Path (Get-Location) 'config.json'
go run ./cmd/easybot
```

浏览器打开 `http://127.0.0.1:5001`。Go 进程同时提供 API 和 `web/dist` 中构建好的页面；日常运行不需要启动 Vite。

需要前端热更新时，在 `web/` 另开终端执行 `npm run dev`，并保持 Go 服务运行。Vite 将 `/api/v1` 请求代理到 `http://127.0.0.1:5001`，其临时端口只用于开发。

| 服务 | 默认地址 | 状态 |
| --- | --- | --- |
| 网页管理台与管理 API | `127.0.0.1:5001` | 由 Go 进程监听 |
| Minecraft 桥接（Bridge） | `127.0.0.1:26991` | 与管理服务共用 HTTP listener，使用 `/bridge` 路径 |

### 可执行程序与数据位置

便携包包含可执行程序、`config.json`、`web/dist`、许可证和使用说明。解压到可写目录后即可运行，默认数据保存在同目录的 `appdata/`，需保留包内目录结构。

开发构建的 `bin/easybotce.exe` 默认读取 `config.json`；程序旁已有配置时优先读取。`go run` 使用临时可执行文件，因此应按上面的示例通过 `EASYBOT_CONFIG` 指定开发配置。

Windows 双击启动失败时，程序显示错误并等待回车关闭；从已有终端或无控制台任务运行时不暂停，返回非零退出码。

## 启动配置

配置文件为 Go 原生结构的 `config.json`，支持 UTF-8 BOM。缺失时自动生成默认配置和 12 位数字管理密码；首次启动时密码仅在控制台显示一次，并写入 `auth.password`。便携包中的配置模板在 Unix 上使用 `0600` 权限；向已有模板写入生成的密码前也会收紧权限。Windows 文件访问范围由目录和文件 ACL 控制。模板见 [config.example.json](../internal/config/config.example.json)。旧版 .NET 配置字段会触发明确迁移错误，不会静默覆盖。

| 配置项 | 说明 |
| --- | --- |
| `server.address` | 管理服务监听地址，默认 `127.0.0.1:5001` |
| `server.allowedHosts` | 允许的请求主机名；支持 `*`、分号分隔的主机名和通配子域名 |
| `server.tls.certificate`、`server.tls.privateKey` | 可选 PEM 证书和私钥 |
| `bridge.address` | Bridge 配置地址，默认 `127.0.0.1:26991`；当前 WebSocket `/bridge` 挂载在管理服务 listener 上 |
| `database.url` | 可选 MySQL 或 PostgreSQL 连接地址 |
| `database.sqlitePath` | SQLite 路径，默认 `appdata/easybot.db` |
| `auth.password` | 管理密码明文配置 |
| `logging.level` | `debug`、`info`、`warn` 或 `error` |

相对路径基于配置文件目录解析。

### 环境变量

相关环境变量优先于 JSON 配置：

| 环境变量 | 用途 |
| --- | --- |
| `EASYBOT_CONFIG` | 指定配置文件 |
| `EASYBOT_ADDR` | 覆盖管理服务监听地址，例如 `127.0.0.1:5001` |
| `EASYBOT_SQLITE_PATH` | 覆盖 SQLite 数据库路径，可指向已有 CE 数据库 |
| `EASYBOT_DATABASE` | 覆盖外部数据库连接地址 |
| `EASYBOT_TLS_CERT`、`EASYBOT_TLS_KEY` | 指定 PEM 证书及私钥文件 |
| `EASYBOT_ALLOWED_HOSTS` | 覆盖允许的请求主机名 |

MySQL 连接格式为 `mysql://user:password@host:3306/database`；PostgreSQL 连接格式为 `postgres://user:password@host:5432/database?sslmode=disable`。后者示例关闭了数据库连接的 TLS，实际连接参数应与数据库部署方式一致。

### HTTPS 示例

```json
{
  "server": {
    "address": "0.0.0.0:5001",
    "tls": { "certificate": "cert.pem", "privateKey": "key.pem" }
  },
  "auth": { "password": "请设置足够强的管理密码" }
}
```

## 登录与访问控制

仅绑定回环地址时，本机可直接进入管理台；绑定非本地地址时需使用 `config.json` 中 `auth.password` 登录。首次启动生成 12 位数字密码，并在控制台显示一次。密码明文保存在配置文件中，应限制文件访问权限；通过公网传输凭据时建议使用 HTTPS。登录后使用 HttpOnly、SameSite=Strict 会话 Cookie，有效期为 7 天；每个远端 IP 在 5 分钟内最多尝试登录 10 次。

## 升级与迁移

升级前停止程序，备份并保留 `config.json` 与 `appdata/`，再替换程序及页面资源。原版 `.NET appsettings.json` 和 `token.txt` 不再用于 CE 启动，请根据新配置示例手动迁移监听、数据库及其他参数。复制启动配置不会导入原版数据库、适配器或插件数据。

## 已实现与待验证范围

管理台和持久化 API 已覆盖适配器、服务器、玩家、账号、群组、允许与拒绝名单、命令定义、AI 服务配置、图片模板目录、JavaScript 插件目录和实例设置。配置数据通过统一记录表保存，启动时执行带版本的数据库迁移；存在配置入口不代表相应运行时已经实现。

OneBot 11 和 QQ 官方 Bot 是当前可运行的适配器。OneBot 11 使用正向 WebSocket；QQ Bot 使用官方 Gateway，按 `AppID`/`AppSecret` 获取 `QQBot` token，并通过官方 OpenAPI 发送群/C2C 消息和读取频道列表。两者都支持身份握手、事件归一化、生命周期控制、状态及能力查询和有限退避重连。OneBot 11 的心跳超时检测默认开启，未收到协议端心跳前使用 15000 毫秒回退间隔，收到带 `interval` 的心跳事件后自动采用协议端间隔；仍可在配置中显式关闭。程序启动时恢复已启用的配置，API 不返回适配器凭据，编辑时留空会保留已保存的密钥或令牌。不支持的平台类型会被拒绝，避免保存成可运行配置。

QQ Bot 配置示例：

```json
{"AppID":"你的机器人 AppID","AppSecret":"你的机器人 AppSecret","Intents":335546371}
```

`APIBase`、`GatewayURL` 和 `TokenURL` 仅用于沙箱或协议模拟测试，默认分别使用 QQ 官方 OpenAPI、Gateway 和 token 地址。QQ 官方 Gateway/WebSocket 链路存在逐步下线及 Webhook 灰度安排，生产使用前应以开放平台当前控制台能力为准；本实现暂不声称支持官方 Webhook 回调。

Minecraft 侧提供与原版插件一致的桥接服务端 `/bridge`：JSON over WebSocket，遵循 `Hello`/`Identify`/`HeartBeat`/`Packet`/`CallBack` 与整数 `op`、snake_case 字段。插件使用服务器记录 `detail.token` 鉴权，令牌在创建记录时自动生成，可通过 `POST /api/v1/servers/{id}/token` 轮换。连接状态取自实际会话并通过 `/api/v1/bridge/status` 暴露；`SYNC_MESSAGE` 聊天按 `sync-rules` 规则转发到 OneBot 11 群，群消息通过 `SEND_TO_CHAT` 推回服务器，双向规则带 5 秒回显抑制。适配器、服务器和同步规则在管理台以表单编辑，其余尚无运行时语义的配置类型保留 JSON 输入。

运行日志保留有界内存缓冲，并通过有界异步队列写入 `runtime_logs`。`/api/v1/logs` 支持日志级别、组件、UTC 时间范围、关键词和分页筛选；`/api/v1/logs/status` 提供保留策略和写入失败计数。日志页面可设置持久化开关、保留天数和最大条数，每小时清理一次。日志会遮蔽常见令牌、密码、数据库连接地址及验证码，默认不记录消息正文。

运行日志会将错误详情、服务器和适配器标识等结构化属性作为键值写入日志内容，支持关键词检索；`With` 和 `WithGroup` 附带的上下文也会保留。凭据属性在写入内存和数据库前整值脱敏，`request_id` 同时保留为独立筛选字段。

以下能力仍待完成或验证：

- **真实环境验证**：OneBot 11 和 QQ Bot 已通过本地协议/API 模拟测试；真实账号、QQ 官方限流、权限和 Gateway 长连接稳定性尚未验证。
- **尚未实现**：QQ 官方 Webhook 回调、Milky、Telegram、OpenQQ 适配器运行时，Minecraft 插件本体、账号绑定、命令执行、JavaScript 插件执行、AI 对话、浏览器图片渲染、模板市场、PlaceholderAPI 与统计求值、平台安装器及 Docker 打包。
- **桥接验证范围**：`/bridge` 仅通过本地模拟插件验证过握手、事件上报和消息下发，尚未用发布的 EasyBot 插件包实测；绑定、命令与 PAPI 类报文只回执不实现。
- **参考边界**：原版 NativeAOT 可执行文件无法通过现有反编译资料可靠重建，独立的 EasyBot-Recovered 仓库仅作为管理 API、模块名称和行为的对照依据。

## 测试与协作

从仓库根目录执行：

```powershell
go test ./...
go vet ./...
cd web
npm run build
```

外部数据库测试使用 `EASYBOT_TEST_DATABASE_DSN` 指定专用空测试库，再执行 `go test -count=1 -vet=off ./internal/store`。测试会创建用户和记录，不得指向生产数据库；未设置该变量时，外部数据库测试会跳过。当前 CI 验证目标为 MySQL 8.4.11、MySQL 9.6.0 和 PostgreSQL 18.6，具体版本以对应集成测试通过为准。
