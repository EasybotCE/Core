# CE 项目结构与原版功能对照

检查日期：2026-11-07。定位：已获授权复刻闭源 EasyBot 的功能和使用流程；CE 是 Go/Vue 独立实现。按单进程、少量管理人员和多个机器人/游戏服连接评估。本次是结构与功能边界检查，不是完整安全审计或协议兼容认证。

## 参考依据

同组织私有仓库 `EasybotCE/EasyBot-Recovered` 已拉到 Core 的同级目录。本次参考 `linux` 分支、提交 `b3f00bc`。

- `decompiled/linux/README.md`：原版 2.2.0-dev.2 发布包恢复记录；34 个产品模块。原版 NativeAOT 主程序无法可靠恢复，WebUI 反编译项目也不能直接重复构建。
- `decompiled/linux/EasyBot.WebUI/EasyBot.New.WebUI.Resources.appsettings.json`：恢复的原版 WebUI 默认端口 26990。
- `decompiled/linux/Modules/EasyBot.Bridge.decompiled.cs`：原版 Bridge 默认端口 8080，注册 `/bridge` WebSocket 路径，包含会话、心跳、识别及请求回调等类型。
- `decompiled/linux/EasyBot.WebUI/EasyBot/New/WebUI/Controllers/`：原版管理 API 及功能入口。
- 参考仓库的 `src/EasyBot` 是另外编写的 .NET 脚手架，不能当作原版实现证据。

私有参考文件继续保留在独立仓库，不并入公开 Core。恢复源码只证明可观察到的功能、接口与行为；缺失代码不推断为已知。

## 原版与 CE 功能差距

| 原版恢复证据 | CE 当前情况 | 下一步验收 |
| --- | --- | --- |
| WebUI Controllers、登录服务 | 管理员初始化、登录、配置 CRUD、运行日志已实现 | Windows/Linux 可重复构建与运行 |
| Adapter.Onebot11/Milky/Telegram/OpenQQ 模块 | OneBot 11 正向 WebSocket 已实现，模拟器已覆盖；其他协议未实现 | 真实账号收发、群发现、限流与重连 |
| Bridge 模块、ServerController | 服务器记录可配置，Bridge 协议与插件未实现 | 身份认证、版本协商、心跳、聊天事件、命令回执 |
| Core、Model、Whitelist 模块 | 玩家、名单、命令、同步规则等可保存配置，未形成消息与绑定闭环 | 群服双向消息、防回环、绑定和权限验证 |
| Ai.OpenAi、AiChatOs、AiController | 有 AI 配置目录，无 AI 对话执行链路 | 超时、限流、上下文与真实调用 |
| ImageTemplate、Skin、NbtLib、MineRenderer | 有模板/皮肤等目录入口，无对应渲染与物品预览链路 | 资源限制、模板渲染和真实预览 |
| Scripting、V8Plugin、Plugin.Api、LGraph.Runtime | 有插件目录，无脚本隔离与执行运行时 | 权限、生命周期、资源上限和故障隔离 |
| DataPersistence、Statistics 模块 | SQLite 默认存储及 MySQL/PostgreSQL 实现；业务多用通用 records 表 | 独立领域约束、迁移和统计口径 |

## 检查发现及处理顺序

1. **必须优先：首个群服消息闭环尚未完成。** 原版服务器页有实际会话与能力查询，CE 目前只有服务器配置，不能把记录数当在线数。先实现 26991 Bridge 与一个真实插件端，再做消息路由、回执及防回环；否则管理台仍无法完成复刻目标的核心任务。
2. **应修复：规划与实现描述有漂移。** 根说明及 PLAN 中仍有适配器尚未实现等早期表述，实际 OneBot 11 运行时已存在；开发说明里的旧本地反编译路径也不成立。本次修正根说明与参考路径，后续逐项按“配置、模拟、真实验证”更新验收表，避免按页面数量计算完成度。
3. **应修复：业务模型仍缺领域约束。** `store.Record.Detail` 是通用 JSON 字符串，`Save` 主要校验类型与名称；玩家绑定唯一性、路由引用和命令权限目前不能依靠该模型完整保证。进入对应运行时开发时增加具体校验、数据库约束与事务测试，不提前新建空模块。
4. **应修复：前端和 HTTP 层职责集中。** `App.vue` 集中导航、登录、所有管理页面、请求及轮询；`web.go` 集中路由、认证与多个业务处理器。并行增加 Bridge、绑定和路由时会频繁修改同文件。按实际功能增量抽取 API 客户端、页面及后端处理器，保留单体架构，不以行数机械拆文件。
5. **应修复：交付验证缺口。** 原 CI 仅 Linux Go 测试/静态检查与前端构建，未持续覆盖 Windows 可执行程序构建。本次扩展 Windows/Linux Go 测试、vet 与构建。仍需后续补齐把前端与 exe 一起交付的发布包流程；当前 exe 依赖 `web/dist`，不能当作单文件发布版。
6. **已补基础规则：所有开发者使用中文提交。** 新增贡献规范、AGENTS 和提交标题检查；既有英文历史保持不变。CI 只能判断标题包含汉字，不能理解是否中文表达。GitHub 必需检查与分支保护需要在远端设置后才能强制所有贡献者遵守中文提交规范。

## 端口与启动约定

- CE 正常运行：5001 同时提供 WebUI 和管理 API；26991 用于 Bridge。对照恢复的原版默认值 26990/8080，二者不重合；用户自行修改过的原版端口不在此结论范围内。
- Bridge 尚未实现，因此目前仅实际监听 5001，不占用 26991。
- 日常运行先构建前端，随后启动 Go/exe；前端由同一进程提供。Vite 仅为可选热更新工具，它的临时端口不属于产品部署端口。
- `EASYBOT_ADDR` 继续支持显式覆盖；外部监听仍遵循既有密钥和 TLS 校验。
