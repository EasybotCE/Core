# 架构概念

本页解释 EasybotCE 的目标架构，不代表所有能力已实现。当前落地范围见[实现状态](implementation-status.md)。设计决策的完整清单和理由见[决议记录](decisions.md)。

## 核心理念

EasybotCE 把**服务器实例作为主体，功能配置作为操作**。用户先接入端点（一个 MC 服务器、一个聊天平台机器人、一个插件进程），再在端点与绑定关系上配置功能。这与"每个功能独立控制一个服务器实例"的思路相反：功能不拥有生命周期，端点才拥有。

## 端点统一模型

系统围绕以下三层组织功能（不是全部持久化实体）：

```
Endpoint（端点）
  └── RoutingBinding（路由绑定，端点之间的多对多关系）
        └── 功能配置（挂在端点或绑定对上）
```

端点有三种类型：

| 类型 | 说明 | 接入方式 |
| --- | --- | --- |
| `mc-server` | 安装了对接插件/MOD 的 Minecraft 服务器 | 主动外拨 WebSocket 到 Hub |
| `chat-bot` | 聊天平台协议端（OneBot11 实现等） | OneBot11 反向 WS 连 Hub；正向 WS 由 Hub 主动连接 |
| `plugin` | 独立进程插件 | 与其他端点相同的 WebSocket 协议 |

三种端点使用统一的**内部端点模型**；MC 与独立插件使用 CE 协议，原生 OneBot11 经适配器接入，不要求外部 BOT 改用 CE 协议。路由绑定关系描述"哪个 bot 和哪个服务器组合"，功能（消息同步、指令桥、黑白名单等）配置在绑定对或端点上。

## Hub 拓扑

主程序（Hub）是常驻守护进程，CE 端点接入以**被动监听**为主：

- MC 与插件主动连接 Hub，计划使用独立 token 鉴权与 wss，MC 无需开放入站端口。
- OneBot11 正向 WS 是 v1 明确需要的主动连接例外；反向 WS 则由 BOT 连接 Hub。
- Hub 持有端点、路由绑定与业务配置，负责鉴权、协议适配、路由和功能执行。
- 其他向外连接扩展留待后续讨论；不由此推导远端 Hub 联邦承诺。

## 协议策略

- MC / 插件的 CE 协议使用 **JSON over WebSocket**，消息带 `v` 版本字段；OneBot11 保持原生协议。
- 连接建立时进行**能力协商**，端点声明自己支持的版本和消息类型。
- 协议采用语义化版本：Hub 兼容当前及上一代 minor 版本，破坏性变更升 major 并保留旧版本过渡期。
- 协议格式以 **JSON Schema** 发布，作为开放生态的契约文档。当前仅实现 `0.1.0` 的握手与消息发布/投递；能力和缺失消息见[协议说明](protocol.md)。

## 插件机制

插件进程就是第三种端点：

- 用与 mc-server 相同的 CE WS 协议接入 Hub。
- 通过 manifest 声明权限范围：订阅哪些事件、可调用哪些 API。
- Hub 按 token 的权限范围做 API 白名单。
- **不兼容 Easybot 原版插件**。1.0 前开发版本的插件 API 标记实验性，不承诺稳定；1.0 发布前评审并明确兼容边界。
- 插件是独立进程：任意语言可写，崩溃不波及 Hub。

SDK（独立仓库 `github.com/EasybotCE/sdk`）提供协议类型定义、WS 客户端和 manifest 工具，语言顺序为 TypeScript 优先，Go 次之。

## 消息同步规则管线

消息同步规则挂在**绑定对**上，不挂全局：

```
[过滤器] → [转换器] → [模板]
```

按序执行。跨服消息同步是同一规则组被多个端点绑定共享。自定义命令、黑白名单等配置同理，跟随"功能配置为操作"的模型。

## 命令身份

聊天触发的服务器命令逐条配置执行身份：

- **控制台身份**：以服务器控制台权限执行。
- **指定玩家身份**：以某个玩家身份执行（需要 MC 端支持，协议中定义对应消息类型）。
- 支持权限不足时的回退行为。

## 图片渲染

图片模板通过 Hub 内嵌 rod 驱动启动无头 Chromium，浏览器本身为独立子进程，对应 Easybot 原版 FULL 版能力，不分轻量/完整档。这不等于另行部署一个渲染 sidecar 服务；后续需落实浏览器安装、沙箱、资源限额与异常回收。

## MC 侧分工

**MC 侧客户端由另一个团队开发**。本项目（Hub）的对接职责是：

1. 协议规范文档：握手、鉴权、消息目录、错误码，附带 JSON Schema。
2. **CLI 参考模拟器**：模拟一个假 mc-server 端点（玩家加入、聊天、命令结果），供 Hub 团队在无真实服务器时自测，也供 MC 团队反向验证实现。

仓库已有可连接 Hub 的诊断模拟器与端到端测试；它不模拟玩家加入/命令结果等尚未实现的业务事件。MC 平台版本和排期由对接团队确认。

## 数据与配置

- **数据库是业务配置的唯一真源**：端点、路由绑定、账号绑定和功能配置都在库中，通过 API 修改生效；业务 YAML/JSON 仅用于导入导出。
- 最小 YAML / 环境变量用于监听、数据库连接与管理员凭据等引导配置，不与业务配置形成双源；端点凭据和路由规则由数据库/API 管理。
- 玩家 ↔ 社交账号的账号绑定不同于端点间的路由绑定；会话、队列等临时连接状态不因此全部持久化。
- 消息同步日志默认不落库，可配置开启并带留存天数。
- 存储支持 SQLite（默认，免 CGO）、MySQL、PostgreSQL。

## 迁移

提供 C# dotnet tool（sidecar）读取 Easybot 原版 LiteDB 数据库，导出 JSON；Hub 提供 `import` 命令导入。迁移范围为**绑定 + 配置**，插件数据因 API 不兼容明确不迁移。
